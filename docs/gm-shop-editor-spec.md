# ГМ-редактор магазину й особистих покращень

Перед початком: прочитати `CLAUDE.md`, `docs/overview.md`. Зразки: каталог рідкісних резервів
(`client/src/pilot/rareReserves.js`, `RareReserveEditor.jsx`) і редактор правил
(`docs/rules-page-spec.md`).

Завдання (від користувача):
1. Магазин — зміна цін будь-якої позиції й додавання нових позицій у відповідні вкладки.
2. Особисті покращення — зміна цін, описів і додавання нових покращень.

## 0. Рішення користувача (16.10.2026)

1. Нова позиція магазину — без окремої механіки: «редактора достатньо». Покупка списує ціну й
   пише запис у журнал операцій.
2. Нове покращення — лише текст і ціна (позначка «придбано», як у «Квантового ліцензування»).
3. Параметри механік редагуються: кап PR з «Трастовим фондом», розмір пачки PR, щаблі
   поповнення зарядів, базовий кап PR, стартові PR.
4. Редактор — окремий розділ ГМ-панелі (`/gm`).
5. Внесок, більший за нову (знижену) ціну покращення, не повертається — як і раніше.
6. Ховати можна будь-яку позицію, зокрема вбудовану.
7. Правила (`/rules`) — окремий текст, з магазином не синхронізуються.
8. Звичайні резерви (`/reserves`) — поза цим завданням.
9. Написи інтерфейсу з §5 — затверджено.

## 1. Що було до зміни

Усе — константи в `client/src/pilot/constants.js` і `repair.js`.

| Вкладка | Ключ | Позиція | Ціна | Механіка (редюсер) |
|---|---|---|---|---|
| PRINTER | kit | 1 ремонтний комплект | 10 PR | `BUY_KITS` one; та сама ціна — докупівля комплектів у ремонті меха |
| PRINTER | kitsfull | Поповнення всіх ремонтних комплектів | 50 PR | `BUY_KITS` full |
| PRINTER | refill | Відновлення лімітних зарядів однієї системи | 30 / 20 / 10 PR | `REFILL_ITEM` |
| PRINTER | prfull | Повний ремонт / передрук меха | 100 PR | `PR_FULL_REPAIR` |
| SHOP | mfull | Повний ремонт / передрук меха | 500 М | `SHOP_BUY` |
| SHOP | core | Заряд Core Power | 250 М | `SHOP_BUY` |
| SHOP | prpack | Printer Requisition · 10 шт | 200 М | `SHOP_BUY`, +10 PR до капу |
| INSURANCE | recover / structure / reactor | поліси меха | PR + М | `INSURANCE_BUY` / `INSURANCE_USE` |
| INSURANCE | clone | Second chance / To hell and back | 2000 М | без зміни стану |

Покращення: `buffer` (кап PR 100 → 200; дзеркалилось у SQL), `insure` (вкладка INSURANCE),
`insure2` (заміна пакета `clone`), `parking` (другий слот меха), `quantum` (лише текст).

## 2. Дані — `supabase/migrations/20261017_shop_catalog.sql`

- `public.shop_items (key pk, kind, grp, title, price_pr, price_mana, params jsonb, archived,
  sort, updated_at, updated_by)`; `kind` — `printer` / `shop` / `insurance` / `upgrade`.
  `params`: `desc`, `upgraded` (поліси); `quote`, `effect[]`, `notes[]`, `requires`, `cap`
  (покращення); `tiers` (refill); `size` (prpack).
- `public.shop_settings` — один рядок: `pr_start`, `pr_cap_base`.
- RLS: читання — будь-який залогінений; запис — лише RPC з `private.is_gm()`:
  `gm_save_shop_item`, `gm_set_shop_item_archived`, `gm_reorder_shop_items`,
  `gm_save_shop_settings`. Вкладку наявної позиції змінити не можна. Ключ нової позиції —
  `c_<12 hex>`.
- `private.pr_cap(st)` — кап PR з каталогу; ним замінено літерали 200 / 100 у
  `gm_close_game`, `gm_resolve_slot`, `private.apply_game_reward` (решта тіл — поточні з бази,
  звірено md5 до зміни).
- Наповнення — `20261017b_shop_catalog_seed.sql`, згенеровано з `defaultCatalog()` дослівно;
  ключі ті самі, що в станах пілотів.

## 3. Клієнт

- `client/src/pilot/shopCatalog.js` — модульний кеш каталогу (`loadShopCatalog`,
  `useShopCatalog`) і синхронні геттери для редюсера (`shopItem`, `onSale`, `kitPr`,
  `limitedRefillPr`, `prCapFor`, `prStart`, `upgradesFor`, `insurancePacks`, …). Поки каталог не
  прийшов або таблиця порожня — значення з `constants.js`.
- Механіку мають лише ключі з `BUILTIN_KEYS`. Нові позиції: PRINTER — `PRINTER_BUY`, SHOP —
  `SHOP_BUY` (списання + журнал), INSURANCE — купівля й використання поліса без зміни стану.
- Приховане не продається (редюсер теж відмовляє), але придбане покращення, внесок і поліс
  пілота лишаються видимими й діють; внесок у приховане покращення можна лише повернути.
- `SHOP_BUY` для повного ремонту за ману — ключ `mfull` (було `fullrepair`).
- Нового пілота `api.createPilot` створює після `loadShopCatalog()` — стартові PR з каталогу.

## 4. Редактор — `client/src/pages/GmShopEditor.jsx`, ГМ-панель → «МАГАЗИН»

- Перемикач розділів ГМ-панелі `ГРАВЦІ` / `МАГАЗИН`.
- Вкладки `PRINTER` / `SHOP` / `INSURANCE` / `ОСОБИСТІ ПОКРАЩЕННЯ` з кількістю.
- PRINTER: панель `PRINTER REQUISITION` — `СТАРТОВІ PR`, `КАП PR`, `ЗБЕРЕГТИ`.
- Список позицій вкладки: назва, група (для покращень), `ПРИХОВАНО`, ціна, `↑ ↓`, меню
  `РЕДАГУВАТИ…` / `ПРИХОВАТИ` / `ПОВЕРНУТИ В КАТАЛОГ`; у шапці `+ ДОДАТИ ПОЗИЦІЮ` /
  `+ ДОДАТИ ПОКРАЩЕННЯ`.
- Вікно позиції: `НАЗВА`, `ЦІНА, М` / `ЦІНА, PR` (за валютами вкладки); refill —
  `1 ЗАРЯД, PR`, `2 ЗАРЯДИ, PR`, `3+ ЗАРЯДИ, PR`; prpack — `РОЗМІР ПАЧКИ, PR`; поліс — `ОПИС`,
  у clone ще `НАЗВА · <назва insure2>` і `ОПИС · <назва insure2>`; покращення — `ГРУПА`,
  `ЦИТАТА`, `ЕФЕКТ` і `УТОЧНЕННЯ` (рядки, `+ РЯДОК`, `✕`), `ПОТРІБНЕ ПОКРАЩЕННЯ` (`—` або інше
  покращення), у buffer — `КАП PR`; `СКАСУВАТИ`, `ЗБЕРЕГТИ` / `ЗБЕРЕЖЕННЯ…`.
