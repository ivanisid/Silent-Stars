# Хроніка — специфікація (етап 1: розділ для ГМів)

Місце, де ГМи ведуть записи кампанії замість блокнота: NPC, фракції, локації та будь-що інше,
звіти зіграних ігор і події світу. Референси — Kanka (типи записів, згадки, приватність),
LegendKeeper (рівні видимості), Obsidian-воркфлоу ГМів (зворотні посилання «де згадано»),
Diarius (хроніка сесій).

## Рішення власника

1. **Доступ запису — три рівні:** `ЛИШЕ Я` (приватний), `ГМИ` (усі ГМи), `УСІ` (ГМи й гравці).
5. **Спільні записи (`ГМИ`, `УСІ`) редагують усі ГМи** (міграція `20261106b_chronicle_gm_edit.sql`).
   Приватний — лише автор. Доступ змінює і запис видаляє лише автор.
2. **Порядок:** спершу розділ для ГМів (цей етап), потім — для гравців.
3. **Хроніка — звіти ігор + події світу.**
4. **Тип довідкового запису задають теги.** Спільний пул тегів: `NPC`, `ФРАКЦІЯ`, `ЛОКАЦІЯ`
   на старті; будь-який ГМ додає новий (наприклад, `КОРАБЕЛЬ`), далі всі обирають його зі списку.

## Дані (міграція `supabase/migrations/20261106_chronicle.sql`)

| Таблиця | Поля | Примітка |
|---|---|---|
| `chronicle_entries` | `kind` (`record` / `report` / `event`), `title`, `body`, `visibility` (`private` / `gms` / `players`), `author_id`, `slot_id` → `game_slots` (лише звіт), `event_date` (лише подія), `created_at`, `updated_at` | |
| `chronicle_tags` | `name` (унікальна без регістру, ≤32), `created_by` | стартові теги — `created_by = null` |
| `chronicle_entry_tags` | `entry_id`, `tag_id` | видалення тегу чи запису прибирає зв'язки |

**RLS:**
- читання запису: автор; `gms` — ГМи; `players` — усі залогінені;
- створення — ГМ, лише від себе; зміна — автор, а спільного запису — будь-який ГМ; видалення — лише автор;
- тригер `chronicle_entries_guard`: автора не змінити, доступ змінює лише автор, `updated_by` / `updated_at` ставляться самі;
- теги: читають усі, додає ГМ, видаляє той ГМ, що додав;
- теги запису видно тим, хто бачить запис; змінює той, хто може змінити запис.

`gm_save_chronicle_entry(...)` (security invoker) зберігає запис і повний набір тегів однією
транзакцією.

Перевірено на базі транзакцією з відкатом: автор бачить 3 свої записи; інший ГМ — 2 (без
приватного), не може змінити чужий запис і видалити чужий тег; гравець — 1 (`УСІ`) і не може
створювати записи.

## Текст запису

Звичайний текст: абзаци через порожній рядок, `**виділення**`, `[текст](https://…)` і згадка
`@[Назва](<id запису>)`. У редакторі `@` + перші літери назви відкривають підказку записів
(стрілки, Enter/Tab, Esc). У перегляді згадка — посилання на запис з його поточною назвою; якщо
запис недоступний читачеві — просто текст. HTML з бази не вставляється.

Логіка — `client/src/chronicle/markup.js`, тести — `markup.test.mjs` (у CI).

## Сторінка `/chronicle` (лише ГМ; пункт `ХРОНІКА` / `CHR` у рейці й таб-барі)

- **Ліворуч — `ЗАПИСИ`:** тип (`ВСЕ / ЗАПИС / ЗВІТ / ПОДІЯ`), теги (обрані разом звужують
  список), пошук у назві й тексті. Порядок — новіші першими: звіт за датою гри, подія за датою
  події, запис за останньою зміною. Меню «⋯» — видалення своїх тегів.
- **Праворуч — запис:** тип, доступ, теги; для звіту — гра й затверджений склад (позивні);
  для події — дата; автор (і `ЗМІНИВ`, якщо останнім змінював інший ГМ); текст; `ЗГАДКИ` — записи,
  що посилаються на цей. `ЗМІНИТИ` — автору й, для спільного запису, будь-якому ГМу; `ВИДАЛИТИ` — автору.
  У редакторі не-автора перемикач доступу неактивний.
- **Редактор:** тип, доступ, гра (звіт; назва гри підставляється в порожню назву), дата (подія),
  назва, теги з додаванням нового, текст із підказкою згадок.
- Телефон: список або запис на весь екран, «‹» повертає до списку.

  гравцям недоступні через RLS `profiles` — потрібна функція або поле).
- Зв'язки з типом між записами (союзник, ворог, член фракції).
- Публікація відкритого звіту в тред гри в Discord.
- Портрети записів через наявні арти.
